# Milestone 0 — Repository assessment and plan

Date: 2026-10-04

## Starting point

- Repository `joyrana/enterprise-ai-application-workspace` was **empty**: no commits, no code,
  no CI, no conventions to preserve. Default branch `main`. Description only.
- There was therefore no existing architecture, technical debt or backward-compatibility
  constraint. Every decision below is new and recorded as an ADR.

## Environment constraints found during the assessment

| Constraint | Effect | Mitigation |
|---|---|---|
| The authoring environment could not reach npm or PyPI (egress policy, HTTP 403) | Dependencies could not be installed or tests run where the code was written | GitHub Actions is the source of verification; lockfiles are generated by the opt-in `regenerate.yml` workflow and committed. No local result is claimed for anything that needs those packages. |
| No model-provider access from the authoring environment | Real-model calls cannot be exercised there | Milestone 2 uses a fake provider plus recorded fixtures; real-model smoke tests run only where credentials and network exist (ADR-0007). |

What *was* executed in the authoring environment: the `appspec` test suite (30 tests, all
passing, using the preinstalled Pydantic 2.13 and jsonschema 4.26 with a minimal stand-in
for pytest), Prettier formatting of the web app, byte-compilation of all Python modules, and
the JSON Schema export. Everything else is verified in CI.

## Highest-priority vertical slice

**Milestone 1 — Foundation.** Exit criterion from the brief: *a user can create a project and
persist a validated specification.* Everything later (skills, orchestration, design systems,
generation) reads and writes the canonical specification, so its contract, validation,
revisioning and persistence come first.

### In scope

1. `packages/application-spec` — canonical spec v1.0.0 (Pydantic), explicit
   unknown/proposed/confirmed status, provenance, referential validation, server-side
   revision stamping, canonical hashing, schema versioning/migration hook, JSON Schema export.
2. `services/api` — FastAPI modular monolith: projects, immutable spec revisions with
   optimistic concurrency (ETag/If-Match), idempotent creation, tenant scoping, audit trail,
   RFC 9457 errors, request ids, body limits, security headers, Alembic migrations,
   OpenAPI export.
3. `apps/workspace-web` — React + Fluent UI v9 workspace: shell, projects list/create,
   project overview (requirement status), spec editor with conflict handling, revision
   history, audit trail. Typed client generated from OpenAPI.
4. CI — lint, format, strict types, unit + PostgreSQL integration tests, contract drift
   checks, production build, dependency audit, secret scan, dependency review.

### Explicitly out of scope for this slice

Model calls, skills, orchestration (Milestone 2); design-system adapters and UI IR
(Milestone 3); code generation and builds (Milestone 4+); real authentication (tracked as a
risk; dev auth is refused in production).

## Acceptance criteria (Milestone 1)

Each criterion names the test that verifies it.

| # | Criterion | Verified by |
|---|---|---|
| A1 | Creating a project returns 201 and persists revision 1 with an empty spec where every fact is `unknown` | `test_create_project_starts_with_empty_spec_at_revision_1` |
| A2 | A valid spec saved with the current ETag creates revision N+1; project name syncs from the spec | `test_save_creates_new_revision_and_syncs_project` |
| A3 | Saving with a stale ETag fails with 412 and leaves data unchanged; missing If-Match → 428 | `test_stale_if_match_is_rejected_with_current_revision`, `test_save_requires_if_match` |
| A4 | Two concurrent saves from the same revision cannot both succeed | `test_concurrent_saves_from_same_revision_cannot_both_win` |
| A5 | Structurally invalid specs and dangling references are rejected with JSON paths | `test_structurally_invalid_spec_is_rejected_with_paths`, `test_dangling_references_are_rejected_with_paths` |
| A6 | Unknown values cannot carry invented data; confirmed facts record who confirmed them; model-sourced facts record skill and model | `test_fact_status_invariants`, `test_model_provenance_requires_skill_and_model` |
| A7 | Revision history is immutable (DB trigger) and every revision remains retrievable | `test_revisions_are_immutable_in_the_database`, `test_revision_history_is_preserved_and_paginated` |
| A8 | Artifact-level revision metadata is server-stamped and changes only for changed elements | `test_only_changed_elements_get_new_revision_stamps`, `test_revision_stamping_tracks_changes_by_id` |
| A9 | Retried creates with the same Idempotency-Key do not duplicate; reuse with another body → 409 | `test_idempotent_create_replays_the_same_project`, `test_idempotency_key_reused_with_different_body_conflicts` |
| A10 | Tenants cannot read or write each other's projects (404, not 403) | `test_tenants_cannot_see_each_others_projects` |
| A11 | Migrations upgrade, downgrade and match the ORM models | `test_migrations_upgrade_downgrade_and_match_models` |
| A12 | The web app creates a project, shows unknown facts honestly, saves with If-Match and explains conflicts and validation errors | `ProjectsPage.test.tsx`, `ProjectPage.test.tsx`, `SpecEditorTab.test.tsx` |
| A13 | Committed OpenAPI, JSON Schema and TypeScript types match the code | CI steps "Generated contracts are up to date" and "Generated API types match the OpenAPI contract" |
| A14 | Production build succeeds; no high-severity vulnerable runtime dependency; no secrets in history | CI jobs `web`, `python` (pip-audit), `secrets` |

## Validation commands

```bash
uv sync --locked
uv run ruff format --check . && uv run ruff check .
uv run mypy packages/application-spec/src services/api/src
DATABASE_URL=postgresql+psycopg://... REQUIRE_DB=1 uv run pytest
uv run python -m workspace_api.export --check --out contracts

cd apps/workspace-web
npm ci && npm run check:api && npm run lint && npm run typecheck && npm test && npm run build
```

## Risks

| Risk | Severity | Handling |
|---|---|---|
| Development auth trusts headers | High if deployed | Refused at startup when `APP_ENV=production`; real IdP is a prerequisite for any shared deployment |
| Dependency versions chosen without local resolution | Medium | Ranges are conservative; CI resolves, locks and tests; failures are fixed before merge |
| JSON editor is a power-user interface | Medium (UX) | Interim; structured section editors arrive with Milestone 2 discovery skills, keeping the same save contract |
| Open-weight model structured-output reliability | Medium | Validate-and-repair strategy, provider capability flags, per-model evals (ADR-0007) |
